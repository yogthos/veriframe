The last few verifications have not moved you forward — they failed, errored, or restated a claim you already tried.

Step back rather than repairing. Repairing a broken encoding usually produces a differently broken encoding, and the branch that keeps repairing is the branch that runs out of turns having proved nothing.

What is worth trying instead:

- **A smaller claim.** One fact per claim. A sub-goal of the same theorem is a different claim and verifies normally — usually the cheapest way forward.
- **A different representation.** Not the same argument re-encoded: a different way of stating what is true. If you have been reasoning about a set, try its indicator function; if about a bound, try what is tight at the extremal case.
- **`retract_rule`**, if a tentative `add_rule` is what broke things.
- **`thesis`**, to say plainly what you now think the shape of the argument is.

Say what you are changing and why before you call anything. A branch that reframes without being able to state what was wrong with the last frame usually returns to it.
